# PMLDL Assignment 1 — Telco Customer Churn MLOps Pipeline

Automated MLOps pipeline with three stages (data engineering, model engineering,
deployment) that retrains and redeploys a churn-prediction model every 5 minutes.

## Repository structure
code/
├── datasets/
│ └── prepare_data.py # data cleaning, outlier removal, train/test split
├── deployment/
│ ├── api/ # FastAPI service
│ ├── app/ # Streamlit UI
│ └── docker-compose.yml
└── models/
└── train_model.py # feature engineering, XGBoost training, evaluation
data/
├── raw/ # source dataset
└── processed/ # generated by prepare_data.py
models/
└── churn_model.pkl # trained artifact (preprocessor + model + threshold)
services/
└── airflow/
├── Dockerfile
└── dags/pipeline_dag.py # schedules the full pipeline every 5 minutes
requirements.txt

## Stage 1 — Data Engineering

`code/datasets/prepare_data.py` loads the raw Telco Customer Churn dataset,
converts `TotalCharges` to numeric and drops rows with missing values, removes
outliers in `tenure`, `MonthlyCharges`, `TotalCharges` via the IQR method, and
splits the data into `data/processed/train.csv` and `data/processed/test.csv`
(80/20, stratified by `Churn`).

## Stage 2 — Model Engineering

`code/models/train_model.py` engineers two extra features (`NumServices`,
`AvgMonthlyCharge`), builds a `ColumnTransformer` (scaling + one-hot encoding),
and trains an `XGBClassifier`. The classification threshold is tuned on F1
score over the test set. Metrics (`roc_auc`, `f1`, `precision`, `recall`) are
logged to Weights & Biases. The trained artifact is saved to
`models/churn_model.pkl`.

## Stage 3 — Deployment

- **API** (`code/deployment/api`) — FastAPI service exposing:
  - `POST /predict` — returns churn probability and decision
  - `GET /health` — health check
  - `POST /reload` — reloads the model from disk without restarting the container
- **App** (`code/deployment/app`) — Streamlit UI with input fields for all
  customer attributes and a "Predict churn" button that calls the API.

Both run in separate Docker containers, wired together via
`code/deployment/docker-compose.yml`.

## Automation

`services/airflow/dags/pipeline_dag.py` defines a DAG (`pmldl_pipeline`) that
runs every 5 minutes:
prepare_data → train_model → reload_api

`reload_api` calls the API's `/reload` endpoint so the freshly trained model
is picked up without rebuilding or restarting the API container.

## How to run

1. Set your Weights & Biases key:
```bash
   $env:WANDB_API_KEY = "your_key_here"   # PowerShell
```
2. From the repository root:
```bash
   cd code/deployment
   docker compose up --build
```
3. Access:
   - Streamlit app: http://localhost:8501
   - API docs: http://localhost:8000/docs
   - Airflow UI: http://localhost:8080 (login: `admin`, password printed in
     the `airflow` container logs on first start)
4. In the Airflow UI, enable the `pmldl_pipeline` DAG toggle - it will then
   run automatically every 5 minutes, retraining the model and reloading it
   into the running API without downtime.

## Notes

- The pipeline was originally trained/validated in Colab; local retraining
  uses pinned `scikit-learn`/`xgboost` versions (see `requirements.txt`) to
  keep the serialized artifact compatible with the API's runtime.
